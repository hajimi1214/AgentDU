# AgentDU V0.6 状态报告

日期：2026-11-23

## 验收状态

V0.6 尚未通过成熟编程 Agent 产品验收。仓库包含凭据处理、任务恢复、用量遥测、MCP stdio 工具、Agent Skills、显式启用的 Python 扩展和配对评测工具。这些能力有本地自动化测试证据。真实多提供商性能、操作系统级命令隔离和完整用户界面尚未验证或尚未提供。

当前没有宣称 AgentDU 的性能优于单模型模式。此次验证没有可用的真实提供商凭据，因此评测器尚未产生真实任务质量、延迟、费用、交接效率或恢复率数据。

## 已实现并经本地验证

- Shell 和 MCP 子进程会过滤继承环境中的已知凭据。会话事件和工具输出会脱敏已知模型密钥，包括通过自定义环境变量名称配置的密钥。
- CLI 通过配置的环境变量读取 API 凭据，不接受可能暴露在进程命令行中的明文密钥参数。
- 自主协作任务持久化私有会话 ID，可显式恢复或切换到其他已配置模型。恢复前会根据 Git 基线检查已保存的工作区。协作进度会写入主会话事件日志。
- OpenAI 兼容响应在流式和非流式模式下保留提供商 Token 用量。只有输入、输出 Token 完整且价格已配置时才计算费用。缺失数据时费用估算不可用。
- MCP stdio 支持初始化、分页发现工具、服务启动与工具调用授权、消息和队列大小限制、子进程环境过滤及进程清理。
- 自动发现 `.agents/skills` 或通过 `--skills-dir` 指定目录中的 Skills。运行时提供技能列表、说明加载和技能目录内文本资源读取。
- 通过 `agentdu.extensions` entry point 加载 Python 插件。插件必须经显式授权并通过 API 版本检查。
- `agentdu-evaluate` 在不同且干净的 Git 工作区中运行单模型和协作模式，要求两边初始 tree 一致，并记录耗时、模型请求数、Token 用量、可用时的费用估算、验收命令结果和配对差异。

## 验证方法

在仓库根目录运行：

```powershell
$env:PYTHONPATH = "src"
python -m compileall -q src tests
python -m unittest discover -s tests -v
```

测试覆盖本地 HTTP 模型接口夹具、通过附带 MinGit 创建的临时仓库、Shell 子进程、MCP stdio 子进程、任务中断和跨模型接管、会话持久化、Skills 目录边界、插件授权和用量汇总。这些是确定性的本地集成测试，不衡量外部模型的编码质量或服务可靠性。

## 产品边界

- 当前应用是命令行工具，没有 Codex 级桌面交互界面、实时协作时间线、模型配置界面或可视化会话查看器。
- Shell 命令仍以当前用户权限执行。授权和凭据过滤不等于操作系统沙箱，命令可以访问工作区外的文件。
- 提供商支持目前限于 OpenAI 兼容 Chat Completions。没有使用用户凭据验证 OpenAI、DeepSeek 或其他真实提供商矩阵。
- 任务恢复采用显式操作。进程重启后会将活动任务标记为中断并保留 worktree 和会话，不会自行判断重放不确定操作是否安全。
- 协作并发和调度限制只作用于单个 AgentDU 进程，没有跨进程全局并发控制或货币支出上限。
- 价格由用户手动配置并用于估算。费用不会与提供商账单、缓存 Token 折扣、图像和音频用量或提供商专属计费语义核对。
- MCP 目前只支持本地 stdio 工具，不支持 Streamable HTTP、资源、提示词、roots、sampling、任务协议或图像/音频负载转发。
- Skills 元数据解析仅支持 `name` 和 `description` 常见标量及块文本写法，并未实现完整 YAML 语法。Skill 内容按不可信项目指令处理。
- Python 插件经授权后在进程内执行任意代码。没有插件签名验证、依赖隔离、版本冲突解析或操作系统级隔离。
- 配对评测工具提供测量记录，但没有代表性基准集、盲测质量规则、统计分析或自动重置项目的能力。用户需要准备初始 Git tree 相同的独立干净工作区。
- 跨模型数据传递没有项目分级、按提供商配置的脱敏策略或可配置的数据防泄漏规则。咨询会收到提供的上下文，实现和审查模型可以读取分配给它们的 worktree。
- 长上下文管理仍使用保守字符估算和省略提示，没有模型专属 tokenizer 或语义摘要。

## 剩余验收工作

1. 为 Shell 和验收命令增加操作系统级隔离，并按平台验证文件访问、进程清理、网络访问和凭据可见性。
2. 增加产品交互界面，支持模型档案、统一会话、任务进度、交接记录、授权决策和恢复操作。
3. 使用至少两个真实提供商在代表性基准上运行配对评测，保存提示词、干净基线、检查结果、模型版本、配置价格、用量完整性和原始测量结果。
4. 增加故障注入测试，覆盖工具执行期间进程终止、并发恢复、提供商不可用、上下文耗尽、MCP 关闭和 worktree 外仓库变更。
5. 为咨询、审查和实现档案建立有文档记录的数据传输控制，并针对实际序列化的提供商请求测试这些控制。
6. 增加跨进程资源核算，或将单进程部署边界写为产品要求。
7. 剩余控制完成后，对候选版本开展独立安全与可靠性验收。

在这些验收项目具备证据前，AgentDU 应继续处于 V0.6 开发阶段，不能宣称与成熟编程 Agent 产品达到同等水平，也不应进入后续里程碑。
