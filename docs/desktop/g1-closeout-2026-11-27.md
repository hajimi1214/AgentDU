## 任务生命周期测试结果

新增桌面 Host 集成测试在受控任务运行期间终止 Host，启动新 Host 后只调用 `workspace.open`。该路径不携带 Electron Main 的 `interruptedTaskCandidates`，证明新 Host 能从项目会话日志找到未终结任务并生成一个 `task.interrupted`。随后两次 `task.recoverInterrupted` 都返回 `already_terminal`。恢复后的会话只包含一个有效任务终态。

自动化覆盖还验证了以下行为。

- 已完成、失败、取消和中断任务的终态在重复扫描时保留。
- Runtime 正常完成和 Renderer 发起的取消分别记录 `task.completed`、`task.cancelled`。
- 中断的工具调用会以待检查结果闭合，不自动重放工具。
- 损坏会话的 `session.read` 返回 `SESSION_READ_FAILED` 和具体事件错误。
- 工作区暂时不可用时，恢复返回 `INVALID_WORKSPACE`，原会话不新增中断终态。

Electron Main 自身退出后的完整 Windows 进程链、启动器恢复和旧会话 UI 恢复仍未直接演练。Host 协议集成测试证明了重新打开项目时的恢复路径，不能单独替代安装版 Electron 崩溃验证。

此前的安装版试运行使用 `APPDATA` 建立隔离目录，但 Electron 仍载入已有的最近项目列表，Provider 状态显示未配置。正常的 `workspace.open` 会重写最近项目记录，因此这次启动刷新了主用户 profile 中的最近项目时间戳。原始时间戳未留存，无法恢复到启动前的精确值。Provider 设置没有保存操作，也未读取凭据。

为避免重复使用主用户 profile，`desktop/src/main/index.ts` 现在支持显式环境变量 `AGENTDU_DESKTOP_USER_DATA_DIR`，并在应用启动初始化时调用 `app.setPath("userData", ...)`。该提交通过 TypeScript/Electron 构建并生成了上述 NSIS 包。由于 Computer Use 检测到窗口有用户输入且随后报告窗口最小化，本轮停止了该实例的后续操作。隔离覆盖尚未在安装版运行中验证。
