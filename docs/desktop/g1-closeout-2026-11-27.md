## B. Provider 安全存储

本轮使用临时档案 `g1-synthetic` 和合成凭据。实际运行环境是最新 Electron 安装版，`safeStorage` 密文写入隔离目录的 `providers.secure.json`。写入的 Runtime `providers.toml` 只含变量名。Runtime 日志没有密钥。源码检查确认 Main 返回 Renderer 的 Provider 列表仅包含公开元数据和凭据可用状态，Preload 没有读取加密 Store 的接口。

已经观察到档案创建、Endpoint 保存、Model ID 更新、首次设为默认以及重启后重新读取配置。尚未完成两个默认档案之间的切换、档案删除、删除后检查子进程环境、Provider 配置导致 Runtime 重启失败时回滚。Renderer 隔离目前有源码证据，缺少独立攻击面运行测试。因此 B 维持 CONDITIONAL PASS。

## E. Main 进程崩溃恢复

验收通过外部进程管理单独终止安装版 Electron Main PID `40404`，没有使用 `/T`。进程关系与退出结果见 [空闲 Main 退出记录](evidence/g1-main-idle-crash-2026-11-27.json)。终止前记录其内嵌 Python Host PID `21336`。临时项目会话只有 `session_created`，没有运行中任务。Host 在 8 秒内退出，安装目录中没有遗留的 Python Host 进程。本项证明空闲状态的子进程清理。

先前重启后的安装版 UI 显示“检测到上次异常关闭”，Runtime 在线，并载入临时项目和合成档案。屏幕交互工具随后报告窗口最小化及用户输入状态，无法继续发送受控任务。本轮没有产生 `task.accepted`，因此没有活动任务 `task.interrupted`、恢复后的会话状态或防重复执行证据。E 保持 NOT VERIFIED。

## F. 真实 Provider 任务

本轮没有在 AgentDU 中配置真实凭据。没有读取 Codex、浏览器或其他客户端的密钥，也没有向此前提供的 Endpoint 发送真实请求。

完成解阻时，请在 AgentDU 桌面应用中打开左下角“模型与 Provider”，新建档案，填写此前提供的 Endpoint `https://apikey.casa/v1`，API 协议选择 Responses API（与你此前给的配置一致），按服务实际返回的模型 ID 填入 Model ID，将真实 API Key 直接输入 API Key 字段，勾选“设为默认模型档案”并保存。随后使用“测试连接”确认 `/models` 可达。密钥只输入 AgentDU 设置界面，不发送到聊天窗口。用户完成配置后，才可在隔离临时 Git 项目运行真实跨文件编程和真实模型任务中断恢复。

## G. G2 方案二次审计

[G2 Runtime 集成方案](g2-runtime-integration.md) 已补全当前实现差距与准入设计。取消状态、取消传播与运行中 Worker 的协作式停止要求已明确。并发与模型调用预算归入 Host 单一资源管理器。Worker 的 task、session、审批身份、权限范围、取消令牌和工作区要求相互隔离。Host 通过 TaskStateRegistry 对每个会话提供唯一 TaskStateStore 写入所有者，并定义拒绝新任务、取消 Worker、等待任务清理、持久化终态、关闭 Coordinator、再关闭 Host 的顺序。

源码尚未实现 G2。G1 未解除前不得把设计审计 PASS 当作 G2 开发准入。
