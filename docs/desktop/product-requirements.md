# AgentDU Desktop 产品需求与定位

版本：D0 方案

基于 AgentDU `main`，`2aa31341feea69ac1f3c3c062ddfba08082129e4`

## 产品定位

AgentDU Desktop 是面向日常软件开发的本地优先桌面 Agent 工作台。用户在一个项目工作区中与主大脑交互，查看真实工具活动和文件差异，并在需要时监督多个独立 Agent 执行、交接和整合工作。

产品不是 CLI 的图形启动器，也不把聊天页面当作完整产品。桌面版应由 AgentDU 自有 Runtime 执行任务，用户可以明确知道模型正在处理什么、操作了哪些文件、哪些命令需要批准，以及怎样审查和恢复工作。

## 目标用户与主要工作

### 核心用户

- 使用本地 Git 仓库开展日常开发的个人开发者或小型工程团队。
- 需要在不同模型、供应商或 Agent 之间切换的开发者。
- 希望以任务和审查记录管理长时间代码工作，而不是只看一次聊天回复的用户。

### 核心任务

1. 打开或切换本地项目，查看仓库状态和既有任务。
2. 选择模型档案，提交自然语言开发任务。
3. 实时观察模型输出、工具调用、运行命令、授权请求、文件修改和测试结果。
4. 在隔离工作区中启动咨询、审查或实现 Agent，并查看任务依赖和负责人。
5. 查看 Diff、运行验收命令、接受或拒绝集成结果。
6. 关闭应用后恢复任务历史，识别未完成和状态不确定的操作。

## 产品原则

### 本地工程状态是事实来源

源文件、Git commit、测试输出、任务事件和会话记录来自真实运行。Agent 叙述不能代替命令退出码、提交 SHA、Diff 摘要和验收结果。已有 `HandoffLedger`、`GitWorkspaces`、任务结果快照和 JSONL session 可以继续充当证据基础。

### 单模型优先，多模型可见

主 Agent 必须能独立工作。协作发生时，界面显示任务分配、目标模型、工作区、基线版本、状态、验证结果、风险与集成动作。子 Agent 私有上下文保持隔离，主会话展示可共享的任务摘要和证据，不拼接完整私有对话。

### 让人能审查、介入和恢复

用户能够暂停或取消可取消的工作、批准或拒绝高风险操作、查看实际命令和工具结果、重新打开任务记录，并对经过验证的变更执行集成。若外部操作可能已经发生但结果不确定，界面应显示“不确定”并要求检查，不得默认为可安全重放。

### 权限按动作明确

文件读取、文件写入、Shell、Git 变更、网络访问、MCP Server 和插件加载需要独立授权策略。审批卡片显示具体目标、命令、工作区、模型及授权范围。一次性授权和持久授权必须分开呈现。

### 简体中文首发

- 首启优先采用系统语言，简体中文环境默认使用 `zh-CN`。
- 所有主导航、设置、权限说明、任务状态、恢复对话框和空状态都有中文文本。
- 英文可作为第二语言加入。语言资源不得散落在组件实现中。
- 模型原始输出、路径、命令和源码保持原样，UI 标签和状态说明本地化。

## 功能需求

### D1 产品框架

- 安装和运行 Windows 桌面应用，不依赖用户全局安装 Python、Node 或 Git 才能启动应用。Git 缺失时明确提示并关闭依赖 Git 的功能。
- 管理本地项目列表、最近工作区、默认设置、启动失败和版本信息。
- 桌面主进程可启动、健康检查、关闭和监督 Python Runtime 子进程。
- 通过带版本的本地消息协议执行会话列表、提交用户消息、接收增量事件和授权答复。

### 单模型开发体验

- 项目内浏览、搜索和只读查看文件。
- 创建与恢复会话，显示流式回复、工具调用、终端命令、Git 状态、错误和恢复提示。
- 支持安全的文件编辑 Diff 审查以及原子写入后的实际文件状态核对。
- 集成终端和任务执行日志，区分 Agent 运行命令与用户手动命令。
- 管理模型供应商、Endpoint、模型名、能力、超时、流式选项和凭据。
- 清楚呈现模型调用异常、退避重试、取消、上下文接近限制和未完成工具调用。

### 多 Agent 工作区

- 显示主 Agent 和每个工作 Agent 的独立任务卡片、会话标识、模型档案、worktree、基线 commit、依赖、状态和最近事件。
- 支持咨询、只读审查、实现委派、接收交接、验证和集成流程。
- 显示结果摘要、变更文件、diff digest、命令证据和验收检查。
- 多任务按项目显示执行状态、阻塞关系和资源使用。
- 在整合前重新核验基线、所有者、版本、工作区干净度、结果快照和验收命令。

### 扩展与设置

- 设置页提供 Provider、MCP、Skills、插件、权限、外观、语言、数据存储、通知和版本管理。
- 扩展有可见来源、权限范围、启用状态、版本和卸载入口。
- 用户可以选择多个模型配置，但模型数量和并发策略由产品配置控制。
- MCP 与插件授权需要提供活动记录，能够区分启动服务、暴露工具和执行工具三种动作。

## 安全和隐私需求

1. Renderer 默认无 Node、文件系统、Shell 和任意网络 API，所有能力通过窄化、参数化 Preload 或主进程请求暴露。
2. 不把模型密钥放在命令行参数、事件日志、会话记录、前端存储或子 Agent 环境中。凭据应通过系统密钥存储保护，并按 Provider 单独注入。
3. 对 Agent 执行的 Shell、MCP 和插件进程设置工作目录、环境变量、超时、输出上限、进程树清理和权限策略。
4. 在 Windows、macOS 和 Linux 上为工作区文件、网络和子进程边界采用平台级隔离方案。批准弹窗和 Git worktree 本身不构成 OS 沙箱。
5. 跨模型数据传递前显示传递范围，支持隐藏密钥和本地私密数据。保留发送给各模型的数据摘要和目标 Provider。
6. 崩溃报告、遥测和任务事件遵循最小采集。默认不上传源码和对话。
7. 用户可以导出和删除本地会话、任务、运行日志及 Provider 配置。

## 非功能要求与验收指标

| 维度 | 验收要求 |
| --- | --- |
| 启动 | 无 API 凭据时可进入设置和项目主页，主进程与 Runtime 启动状态可视 |
| 响应 | 长模型调用期间 UI 保持可交互，流式输出和工具进度持续更新 |
| 稳定性 | 后端退出、协议错误、磁盘写入失败和应用意外关闭都有可见错误与恢复路径 |
| 正确性 | 会话事件序号连续，用户重试不会创建重复 turn，任务集成前的 SHA 和 Diff 可核验 |
| 安全 | UI 不能绕过 Runtime 权限策略。未经授权的写入、Shell、MCP 启动和插件加载必须被拒绝 |
| 可访问性 | 关键流程支持键盘导航、屏幕阅读标签和足够对比度 |
| 本地化 | 首发核心交互无未翻译的英文界面文案，错误信息保留可检索的技术细节 |
| 评测 | 通过真实模型凭据验证 Provider、工具调用和流式响应。测试报告记录模型版本和环境 |

## 明确不纳入 D0 和 D1 的范围

- D0 仅研究和制定桌面方案，不实现 UI 或修改 Agent Runtime。
- D1 完成桌面壳、Runtime 通信和最小工作流，不建立完整自主多模型策略。
- 复杂插件商店、远程开发环境、云端任务执行、组织级管理和同步服务不作为首版阻塞项。
- 不宣称安全隔离、性能优势或成熟产品能力，除非相应目标平台测试已有证据。

## AgentDU 独特价值

- **事实**：AgentDU 已有自己的 Agent Runtime、会话日志、任务调度、Git worktree、Handoff 账本、结果快照和验收集成机制。
- **推断**：桌面产品的差异化应来自本地工程状态、跨模型任务边界和可验证交接之间的一致模型，而不只是同时提供多个模型入口。
- **待验证**：相同任务下多模型协作是否提升成功率、质量或交付速度，需要基于匹配初始代码状态的单模型与多模型配对评测。
