# AgentDU V0.6 Status

Date: 2026-11-23

## Acceptance State

V0.6 is not accepted as a mature programming-agent product. The repository now contains productization work for credential handling, task recovery, usage telemetry, MCP stdio tools, Agent Skills, explicitly enabled Python extensions, and paired evaluation. These capabilities have local automated evidence. Live multi-provider performance, OS-level command isolation, and a complete user interface remain unverified or unavailable.

No performance advantage over a single-model run is claimed. No real provider credentials were available for this validation, so the evaluation harness has not produced real task quality, latency, cost, handoff efficiency, or recovery-rate measurements.

## Implemented and Locally Verified

- Shell and MCP subprocesses filter known credentials from inherited environment values. Session event data and tool output redact known profile secrets, including keys configured under custom environment-variable names.
- The CLI accepts API credentials through configured environment variables and rejects raw API-key command-line arguments, which would be visible in the process command line.
- Autonomous tasks persist private session identifiers and can be explicitly resumed or handed to a different configured model. Saved workspaces are checked against their recorded Git baseline. Collaboration progress is written to the main session event log.
- OpenAI-compatible responses retain provider token usage across streaming and non-streaming calls. Cost estimates require complete input/output token counts and configured input/output rates. Missing usage makes the estimate unavailable.
- MCP stdio support performs initialization, tools discovery with pagination, permission checks for server startup and individual tool calls, bounded message size and queue handling, environment filtering, and process cleanup.
- Skills are discovered in `.agents/skills` or explicit `--skills-dir` paths. The runtime exposes list, instruction-load, and skill-local text-resource tools with directory-bound path checks.
- Python extensions can be loaded from `agentdu.extensions` entry points by explicit `--plugin` name after execution approval. The extension API version is checked before registration.
- `agentdu-evaluate` runs paired solo and collaborative tasks on distinct clean Git workspaces with matching initial tree hashes. It records wall time, model-request count, provider token usage, estimated cost when complete, check results, and paired metric deltas.

## Verification Evidence

Run the test suite from the repository root with:

```powershell
$env:PYTHONPATH = "src"
python -m compileall -q src tests
python -m unittest discover -s tests -v
```

Tests exercise local HTTP provider fixtures, real temporary Git repositories through bundled MinGit, shell subprocesses, MCP stdio subprocesses, task interruption and cross-model takeover, session persistence, skill directory boundaries, plugin authorization, and usage aggregation. These are deterministic local integration tests. They do not measure an external model's coding quality or service reliability.

## Product Boundaries

- The application is a command-line interface. There is no Codex-level desktop interaction surface, live collaboration timeline UI, model configuration screen, or visual session inspector.
- Shell commands still execute as the current user. Approval and credential filtering do not provide an OS sandbox. A command can access files and processes outside the workspace.
- Provider support remains limited to OpenAI-compatible Chat Completions. No live OpenAI, DeepSeek, or other provider matrix has been tested with user credentials.
- Task recovery is explicit. A restart marks active work interrupted and preserves the worktree and session. It does not autonomously decide whether replaying an uncertain operation is safe.
- Collaboration limits and worker scheduling are local to an AgentDU process. There is no cross-process global concurrency or monetary spending limit.
- Price data is manually configured and used for estimates. Provider invoices, cached-token discounts, image/audio usage, and provider-specific billing semantics are not reconciled.
- MCP currently supports local stdio tools. It does not support Streamable HTTP, resources, prompts, roots, sampling, task protocol, or image/audio payload forwarding.
- Skills metadata parsing supports common scalar and block forms for `name` and `description`. It does not implement all YAML syntax. Skill content is read as untrusted project instructions.
- Python plugins execute arbitrary code in-process after approval. There is no plugin signature verification, dependency isolation, version conflict resolver, or OS-level containment.
- The paired evaluator provides measurements but no representative benchmark corpus, blinded quality rubric, statistical analysis, or automatic project reset. The evaluator requires the user to prepare separate clean workspace copies with matching Git trees.
- Cross-model data transfer has no project classification, provider-specific redaction policy, or configurable data-loss-prevention rules. Consultations receive the supplied context, while implementation and review models can inspect their assigned worktree.
- Long-context management still uses a conservative character estimate and omission notices rather than model-specific tokenizers or semantic summarization.

## Remaining Acceptance Work

1. Add OS-level isolation for shell and acceptance commands, with platform-specific tests for filesystem access, process cleanup, network access, and credential visibility.
2. Add a product interaction surface for model profiles, unified sessions, task progress, handoff history, approval decisions, and recovery actions.
3. Run the paired evaluator on a representative benchmark with at least two real providers. Preserve prompts, clean baselines, check results, model versions, configured prices, usage completeness, and raw measurement outputs.
4. Add failure-injection tests for process termination during tool execution, concurrent resume attempts, provider outages, context exhaustion, MCP shutdown, and repository mutation outside the worktree.
5. Establish documented data-transfer controls for consultation, review, and implementation profiles, and test those controls against actual serialized provider requests.
6. Add cross-process resource accounting or state the single-process deployment boundary as a product requirement.
7. Run an independent security and reliability review on the accepted candidate after the remaining controls land.

AgentDU should remain in V0.6 development until these acceptance items have evidence. It is not ready to claim parity with mature coding-agent products or to begin a later product milestone.
